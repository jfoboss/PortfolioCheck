# PortfolioCheck — инструкции для агента

Настольное приложение для macOS (Python 3.12 + PySide6) — сверяет портфель в Т-Инвестициях (T-Invest API, gRPC)
с правилами пользователя. Интерфейс, документация, комментарии и коммиты — **на русском**.

## Команды

- Окружение: `./bootstrap_mac.sh` (Python 3.12 через Homebrew, `.venv`, зависимости); для тестов ещё
  `.venv/bin/pip install -r requirements-dev.txt`
- Запуск из исходников: `.venv/bin/python app.py`
- Тесты: `.venv/bin/python -m pytest -q` — offscreen, без сети, с временным HOME (см. `tests/conftest.py`)
- Сборка: `./build_mac.sh` → `dist/PortfolioCheck.app` и `.dmg` (только на macOS)
- Перед каждым коммитом/push: `scripts/check_private.sh` — ищет личные данные в исходниках

## Жёсткие правила

1. **Никаких личных данных в репозитории.** Всё личное (классификация бумаг, заморозки, чёрный список, суммы,
   id счёта) живёт только в конфиге пользователя вне репозитория (`~/Library/Application Support/PortfolioCheck/`
   или iCloud). В коде — только нейтральные дефолты; демо — только вымышленное (`demo_snapshot.json`).
   Скриншоты `check_private.sh` не проверяет — их содержимое согласуй с пользователем.
2. **Не читай и не печатай секреты.** Токен T-Invest и ключи ИИ — в Keychain (`secrets_store.py`). Не добавляй
   логирование, которое может их вывести. Токен только на чтение; программа никогда не отправляет заявки.
3. **Программа считает и подсвечивает, решения — за человеком.** Никаких формулировок «купи/продай» в UI и
   промптах ИИ. Инвестиционные советы в ответах пользователю не давать.
4. **Не блокировать UI-поток.** Любая сеть и тяжёлые расчёты — в `QThread`-воркерах; новый воркер добавь в
   `MainWindow.WORKERS`, иначе приложение упадёт с SIGABRT при выходе (живой `QThread` при уничтожении).
5. **Всё, что уже на диске, показывается при старте сразу**, сеть — только догружает. Не обнулять панели при
   пересчёте: старый контент остаётся, в углу крутится `BusySpinner`.
6. **Лимиты бесплатных моделей OpenRouter — общие на аккаунт** (50 запросов/сутки без покупки кредитов).
   Любая новая ИИ-функция обязана идти через кэш `ai.ResponseCache` и по возможности объединяться в один
   запрос с существующими. Подробности — `.claude/rules/ai.md`.
7. Каждая исправленная ошибка — тест в `tests/` с пометкой «Регресс:» в docstring. Прогоняй весь набор.

## Грабли, на которые уже наступали

- **Меняешь формат конфига или удаляешь дефолт, от которого зависят данные** — подними
  `config_migrate.CURRENT_VERSION` и добавь шаг в `MIGRATIONS` (старые значения — замороженной копией, не ссылкой
  на константу), обнови шаблон `config.yaml`. Дефолты к данным пользователя в коде не домешивай.
- **Кэш без «структурного» отпечатка отдаёт устаревшее.** Смена состава бумаг или текста промпта должна
  пробивать интервал кэша (`subjects_fingerprint` включает хэш промпта). Меняешь промпт — это автоматически
  инвалидирует кэш; не обходи это.
- **Ключ автоподстановки в прогнозе = имя поля + `_auto`** (`price_growth_pct_auto`, не `price_growth_auto`),
  иначе настройка не переживает перезапуск.
- **Класс без данных — не ноль.** В средневзвешенных (доходность, рост цен) классы без данных исключаются с
  перенормировкой весов и явно перечисляются в подписи.
- **Перерисовка не должна запускать загрузку**, которая по завершении снова вызывает перерисовку — так
  получился бесконечный цикл догрузки свечей скринера (см. `_enriched_key`).
- **Многострочные `QLabel` в `QFormLayout`** запоминают высоту от минимальной ширины — используй
  `AutoHeightLabel` из `settings_dialog.py`; скрывать строки формы — `QFormLayout.setRowVisible`.
- **Модальные окна в тестах** (`SetupWizard.exec`) подменяй, иначе тест зависнет.
- **MOEX ISS убрал `/securities/{t}/dividends`** — фундаментал и дивиденды берём из T-Invest
  (`GetAssetFundamentals`, `GetDividends`).
- **RSS грузится с системными корнями TLS**, а не с бандлом для T-Invest (у сайтов другие УЦ); ленты бывают Atom.
- **codesign — строго после правки Info.plist**, иначе Keychain отдаёт `SecAuthFailure` (см. `build_mac.sh`).

## Стиль работы

- Пользователь — инженер (SRE/инфраструктура), ценит прямоту и честную оценку. Если задача упирается во внешнее
  ограничение (лимит API, отсутствие данных) — скажи прямо, не маскируй обходом.
- Коммит: первая строка — что сделано (по-русски, до ~70 символов), затем пустая строка и пункты «что и почему».
- Меняешь поведение — обнови README (раздел для пользователя) и при необходимости `docs/`.
