# Платформы и интерфейс

## Сейчас (версия 1.2+)

PortfolioCheck работает на **macOS, Windows и Linux** из одного кода на PySide6. Решение (BACKLOG, п. 12):
первая версия под Windows и Linux — на текущем Qt; смену UI-технологии рассматриваем позже, по результату.

| | macOS | Windows | Linux |
|---|---|---|---|
| статус | основная платформа автора | первая версия, проверка в CI | первая версия, проверка в CI |
| сборка | `build_mac.sh` → `.dmg` | `build.py` → zip | `build.py` → tar.gz (+ `.desktop`, `install.sh`) |
| секреты | Keychain (`/usr/bin/security`) | Credential Manager (keyring) | Secret Service (keyring), без него — файл 0600 |
| данные | Application Support / iCloud | `%APPDATA%` | `~/.local/share` |
| подпись кода | ad-hoc (решено: пока без Developer ID) | нет (SmartScreen) | не требуется |

- Различия ОС в коде — `osutil.py` (платформа, подписи сочетаний клавиш, шрифт, имя хранилища секретов) и
  `paths.py` (папки). Остальной код про ОС не знает.
- CI (`.github/workflows/ci.yml`) на каждом push: тесты на трёх ОС, сборки трёх вариантов, запуск собранной
  программы в демо. Релиз (`release.yml`) прикладывает dmg, zip и tar.gz к релизу на GitHub.
- Ядро за API не выносим (п. 9 отложен: второго интерфейса и веб-версии не будет).
- Открытые вопросы: установщик Windows (Inno Setup / MSIX) вместо zip, AppImage / Flatpak для Linux, подпись кода —
  по потребности.

## История решения (оценка на момент выбора, сентябрь 2026)

Ниже — исходная оценка, по которой выбирали путь. Порт на Qt занял ~35 правок, как и оценивалось.

### Исходная точка

- Стек PySide6 + Python **уже кросс-платформенный**: тот же код запускается на Linux — на нём гоняются все тесты
  (offscreen) и снимаются скриншоты окна. Windows Qt поддерживает так же.
- Код: ~7,5 тыс. строк Python, из них интерфейс (`app.py`, `settings_dialog.py`, `forecast.py`, `charts.py`,
  `wizard.py`, `diagnostics.py`) — ~4,7 тыс. Ядро (~2,8 тыс.) от Qt не зависит.
- Привязка к macOS точечная — ~35 мест в 7 файлах:

| что | где | замена для Windows | оценка |
|---|---|---|---|
| папка данных `~/Library/Application Support`, iCloud Drive | `paths.py`, `portfolio_check.py`, `make_ca_bundle.sh` | `%APPDATA%\PortfolioCheck` (через `QStandardPaths` или `platformdirs`); iCloud — только на macOS, «другая папка» (OneDrive, Dropbox) уже есть | 0,5 дня |
| секреты через `/usr/bin/security` | `secrets_store.py` | Windows Credential Manager через `keyring` (проблема с подписью, из-за которой `keyring` отвергли, — только macOS); запасной файл уже есть | 0,5–1 день |
| бандл сертификатов (корень Минцифры для gRPC) | `make_ca_bundle.sh` (bash) | переписать на Python, вызывать из Настроек — полезно и на macOS | 0,5 дня |
| ссылки `x-apple.systempreferences:`, баннер про TCC | `app.py` | на Windows не показывать | 0,2 дня |
| сборка: PyInstaller + `.app`/`.dmg`, ad-hoc codesign | `build_mac.sh` | PyInstaller `--onedir` + установщик (Inno Setup или MSIX); подпись кода для Windows (без неё SmartScreen пугает пользователя — сертификат платный, решение за пользователем) | 2–3 дня |
| шрифты, размеры, ⌘-сочетания, трей | `app.py`, `charts.py` | `QKeySequence.StandardKey`, проверка HiDPI 125/150 %, иконка `.ico` | 1–2 дня |
| CI | нет | GitHub Actions: тесты на `ubuntu`, `windows`, `macos`; сборка артефактов | 1 день |

**Итого порт на Windows без смены стека — ~1–1,5 недели**, дальше — прогон у заказчика на реальной Windows.
SDK T-Invest — чистый Python + `grpcio` (колёса под Windows есть), ставится так же, с GitHub.

### Варианты «красивого современного» интерфейса

| вариант | что это | трудоёмкость | плюсы | минусы |
|---|---|---|---|---|
| **A. Qt Widgets + своя тема** | QSS-стили, свои компоненты (карточки KPI, таблицы, графики уже на QPainter) | 1–2 недели | один язык и рантайм, риск минимальный, всё текущее сохраняется | потолок дизайна ниже веба; анимации и сложная вёрстка трудоёмки |
| **B. Qt Quick (QML) на PySide6** | декларативный UI, GPU-рендеринг, современные контролы | 4–6 недель (переписать экраны) | остаёмся на Python, плавность и анимации как в мобильных приложениях | новая технология, меньше готовых компонентов для таблиц и графиков, агенту сложнее проверять |
| **C. Electron + Python-ядро** | UI на TypeScript/React, ядро — отдельный процесс (PyInstaller) с локальным JSON-API | 6–10 недель | любой дизайн, огромная экосистема (графики: ECharts/visx, таблицы: AG Grid/TanStack), одинаковый Chromium на всех ОС, UI проверяется Playwright (браузер в моём окружении уже есть), путь к веб-версии | два рантайма; установщик ~150–250 МБ; два процесса и API между ними; подпись и обновления сложнее; переписывается ~4,7 тыс. строк интерфейса |
| **D. Tauri + Python-ядро** | как C, но оболочка на Rust и системный WebView | 6–10 недель | установщик в разы меньше, меньше памяти | рендеринг различается (WebView2 / WKWebView / WebKitGTK) — «одинаково красиво везде» не гарантировано; Rust в сборке |

SwiftUI (BACKLOG, бывший п. 9) с Windows несовместим — при курсе на Windows его стоит снять.

### Общий шаг для C и D — и полезный в любом случае

Ядро за локальным JSON-API (бывший п. 9, первая половина): `core/` без Qt, воркеры → вызовы API, состояние — на
стороне ядра. Это же разрезает `app.py` (п. 6) и делает ядро проверяемым целиком без интерфейса. **2–3 недели.**
После этого UI-технологию можно менять без риска для расчётов.

### Рекомендация агента (обсуждаемо)

1. **Сейчас — Windows на текущем стеке** (1–1,5 недели) + CI на трёх ОС. Это закрывает заказ быстро и почти без
   риска; заказчик получает рабочую программу, а не ждёт переписывания.
2. **Параллельно — вынести ядро за API** (2–3 недели). Нужно для любого будущего UI.
3. **Потом — решать про UI** на живом прототипе: один экран («Обзор») на Electron поверх API — 1 неделя. Если
   результат заметно лучше Qt с темой — переводить экраны по одному; если нет — вариант A.

Моё мнение: Electron оправдан, если важны дизайн и будущая веб-версия, и приемлемы размер установщика и два
рантайма. Для настольной программы одного пользователя с заказом «под Windows» переход не срочный — порт на Qt
даёт результат быстрее, а решение про Electron лучше принимать после выноса ядра, когда он станет дешевле.

### Вопросы к пользователю

- Что именно нужно заказчику: та же программа под Windows или своя версия (брокер, язык, правила)?
- Подпись кода для Windows (сертификат ~$200–400/год) — покупаем или живём с предупреждением SmartScreen?
- Критерий «красиво»: есть ли референсы (приложения, сайты), на которые ориентироваться?
- Нужна ли в перспективе веб-версия или мобильная — это главный аргумент за C/D.
